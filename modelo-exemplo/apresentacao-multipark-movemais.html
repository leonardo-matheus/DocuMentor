Tecnologias de Identificação

Como identificamos os veículos: OCR (câmera) vs RFID (tag)

📷

OCR

Optical Character Recognition

🔍

Como Funciona

Câmera fotografa a placa do veículo e um software de IA identifica os caracteres automaticamente

⚡

Velocidade

Processamento em menos de 1 segundo após a captura da imagem

🎯

Precisão

95-99% de acerto em condições normais de iluminação e limpeza da placa

💰

Custo

Sem custo para o cliente — não precisa de dispositivo no veículo

⚠️

Limitações

Pode falhar com placas sujas, danificadas ou em condições de baixa luz

📡

RFID

Radio-Frequency Identification

🔍

Como Funciona

Tag eletrônica no veículo é detectada por antenas de rádio frequência na entrada/saída

⚡

Velocidade

Detecção instantânea — menos de 100ms para identificação

🎯

Precisão

99.9% de acerto — identificação por código único da tag

💰

Custo

Requer tag no veículo (R$ 15-50) e antenas no estacionamento

✅

Vantagens

Funciona em qualquer condição climática, sem interferência de sujeira

🔄 Processo de Identificação

Comparação visual do fluxo de cada tecnologia

✅

Melhor dos Dois Mundos

O sistema MoveMais suporta ambas as tecnologias simultaneamente. No OCR, o Dionisio recebe a leitura da integradora e valida. No RFID (WPS), a EasyAccess lê a TAG MoveMais e consulta nossa API para verificar se o veículo está apto, depois passa a resposta para o WPS liberar a cancela e encaminha para a Multipark.

Troubleshooting — Diagnóstico por Sintoma

Clique no sintoma para ver as possíveis causas

🚫

Veículo não conseguiu ENTRAR

Clique para ver as possíveis causas

▼
● Veículo já está no pátio (dessincronização) ▼

Causa: Veículo saiu fisicamente mas a notificação de saída não foi recebida pelo MoveMais. Cada sistema mantém seu próprio controle de pátio.

🏢 Dois Pátios, Uma Realidade

🏢 RESPONSÁVEL: INTEGRADORA + MOVEMAIS

Falha na comunicação da saída entre Integradora → MoveMais

Cenários comuns:

  • Saída sem notificação (API falhou)
  • Queda de internet durante saída
  • Liberação manual pela cabine

Diagnóstico: Comparar veículos no pátio MoveMais vs Integradora. Verificar logs de saída.

✅ Tratativa: Executar saída forçada via painel admin ou endpoint /api/vehicle/force-exit/{plate}

● Vagas reservadas da empresa esgotadas ▼

Causa: Empresa X contratou N vagas mas tem mais veículos cadastrados. Todas as vagas estão ocupadas.

🏢 RESPONSÁVEL: INTEGRADORA + MULTIPARK

⚠️ MoveMais NÃO recebe nenhuma informação sobre vagas. Controle é 100% local.

Diagnóstico: Verificar quantos veículos da empresa estão no pátio vs quantidade contratada (sistema da Integradora).

✅ Tratativa: Motorista deve apertar botão para retirar ticket e entrar como avulso. Ou aguardar liberação de vaga.

● Placa lida incorretamente pelo OCR ▼

Causa: Placa suja, iluminação ruim, reflexo ou caracteres ambíguos (O/0, I/1, B/8).

🏢 RESPONSÁVEL: INTEGRADORA

Câmera OCR é equipamento da integradora. Dionisio apenas recebe a leitura.

Diagnóstico: Verificar confidence score no log. Abaixo de 85% indica problema.

✅ Tratativa: Sistema tenta variações comuns (O↔0, I↔1). Se confidence < 70%, solicita releitura ou usa TAG RFID.

● Contrato ainda não sincronizado ▼

Causa: Novo cadastro ainda não propagou para o Dionisio local.

🏢 RESPONSÁVEL: MOVEMAIS

Latência de sincronização Hermes → Dionisio (até 60s)

Diagnóstico: Verificar data de criação do contrato, logs de webhook, status no Hermes.

✅ Tratativa: Forçar refresh da base via endpoint /api/sync/contracts. Tempo de propagação: ~60s.

● TAG RFID não detectada (WPS) ▼

Causa: TAG danificada, mal posicionada no veículo, ou antena com problema.

🏢 RESPONSÁVEL: INTEGRADORA (WPS)

Equipamento RFID é da integradora WPS. MoveMais não tem acesso.

Diagnóstico: Verificar se antena está operacional, testar com outra TAG conhecida.

✅ Tratativa: WPS não suporta OCR. Cliente deve verificar TAG ou usar entrada manual pela cabine.

🚧

Veículo não conseguiu SAIR

Clique para ver as possíveis causas

▼
● Veículo não registrou entrada no sistema ▼

Causa: Veículo entrou por liberação manual ou falha no registro de entrada.

🏢 RESPONSÁVEL: INTEGRADORA + MULTIPARK

Operador da cabine liberou manualmente ou câmera/antena falhou

Diagnóstico: Buscar placa nos logs de entrada. Se não existe, foi liberação manual.

✅ Tratativa: Operador deve registrar entrada retroativa ou liberar saída manualmente.

● Pagamento não confirmado (avulso) ▼

Causa: Cliente avulso não pagou ou pagamento não foi confirmado pelo sistema.

🏢 RESPONSÁVEL: INTEGRADORA + MULTIPARK

Totem de autoatendimento / sistema de pagamento local

Diagnóstico: Verificar status do ticket na bilheteria. Confirmar se pagamento foi processado.

✅ Tratativa: Cliente deve efetuar pagamento. Se já pagou, operador confirma manualmente.

● Timeout na comunicação com integradora ▼

Causa: Latência de rede ou servidor da integradora lento/indisponível.

🏢 RESPONSÁVEL: INTEGRADORA

Rede local ou infraestrutura da integradora

Diagnóstico: Verificar tempo de resposta da API, ping para servidores, logs de timeout.

✅ Tratativa: Cache local de credenciados. Se API demorar >2s, libera pelo cache.

● Placa lida diferente da entrada ▼

Causa: OCR leu placa diferente na saída vs entrada (ex: ABC-1234 vs A8C-1234).

🏢 RESPONSÁVEL: INTEGRADORA

Software de OCR / condições de iluminação

Diagnóstico: Comparar imagens capturadas na entrada e saída.

✅ Tratativa: Sistema tenta variações. Se não encontrar, operador corrige manualmente.

💀

Sistema não responde

Clique para ver as possíveis causas

▼
● Queda de energia alterou IPs ▼

Causa: Equipamentos receberam novo IP via DHCP após reinício.

🏢 RESPONSÁVEL: MULTIPARK

Configuração de rede / DHCP do roteador local

Diagnóstico: Dionisio não consegue se conectar. Logs mostram timeout de conexão.

✅ Tratativa: Configurar IP fixo/estático em equipamentos críticos ou reservar IP por MAC no DHCP.

● Dionisio parou de executar ▼

Causa: Serviço Java parou por erro, falta de memória ou reinício do servidor.

🏢 RESPONSÁVEL: MOVEMAIS

Infraestrutura local (Raspberry Pi / servidor) - software MoveMais

Diagnóstico: Verificar status do serviço, logs de erro, uso de memória/CPU.

✅ Tratativa: Reiniciar serviço Dionisio. Configurar restart automático via systemd.

● Câmera OCR / Antena RFID desconectada ▼

Causa: Cabo de rede desconectado, equipamento desligado ou com defeito.

🏢 RESPONSÁVEL: INTEGRADORA

Equipamento físico / instalação da integradora

Diagnóstico: Ping para IP do equipamento. Verificar LEDs e cabos.

✅ Tratativa: Reconectar cabo, reiniciar equipamento. Se persistir, acionar suporte técnico.

🔄

Dados inconsistentes

Clique para ver as possíveis causas

▼
● Pátios dessincronizados (MoveMais vs Integradora) ▼

Causa: Veículo consta em um pátio mas não no outro. Geralmente por falha de comunicação.

🏢 RESPONSÁVEL: INTEGRADORA + MOVEMAIS

Comunicação API entre sistemas falhou

Diagnóstico: Comparar lista de veículos no pátio em ambos os sistemas.

✅ Tratativa: Hermes monitora e força reconciliação. Endpoint de reconciliação compara ambos os pátios.

● Cobrança duplicada no cliente ▼

Causa: Retry da API criou transação duplicada ou leitura dupla do OCR.

🏢 RESPONSÁVEL: INTEGRADORA ou MOVEMAIS

Depende: OCR leu duas vezes (Integradora) ou retry de API (MoveMais)

Diagnóstico: Verificar logs de transação, comparar timestamps. Identificar se houve retry.

✅ Tratativa: Controle de idempotência. Entradas com <5min de intervalo são ignoradas. Estorno automático.

● Liberação manual pela cabine sem registro ▼

Causa: Operador liberou cancela manualmente sem registrar no sistema.

🏢 RESPONSÁVEL: MULTIPARK

Operador da cabine / procedimento operacional

Diagnóstico: Veículo está fisicamente fora mas sistema mostra dentro.

✅ Tratativa: Treinar operadores para sempre registrar. Usar saída forçada quando necessário.

📡 WPS — Como Funciona o RFID

O fluxo RFID utiliza a infraestrutura da EasyAccess para identificação e controle de acesso via TAG RFID.

EasyAccess

Provê sistemas e infraestrutura baseados em tecnologia sem fio, por identificação de rádio frequência (RFID) e imagens, para gestão centralizada e assertiva dos pátios.

  • Sistema de controle multi-plataforma
  • Fluxo de entrada/saída de veículos
  • Controle de mensalidades e convênios
  • Integração on-line com ERP

📋 Resumo do Processo
  1. Antena RFID detecta a TAG MoveMais do veículo
  2. EasyAccess lê os dados da TAG e consulta a API MoveMais
  3. MoveMais verifica em nosso banco se o veículo está apto para passar
  4. Resposta é devolvida para EasyAccess
  5. EasyAccess repassa para WPS fazer a liberação da cancela
  6. Após liberação, WPS encaminha registro para Multipark
